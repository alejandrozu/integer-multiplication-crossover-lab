cutoff, not the actual first crossing or a hardware runtime prediction.

## 2. Sum the actual word's height increments

The primary source is
[FINITE-TEMPLATE-CLOSURE.md, Sections3–4](https://github.com/CrocSwap/integer-mult-bounds/blob/7c472563474e60185e6ca101a17622133d047e56/research/kappa-rebuild/transfer-audit/FINITE-TEMPLATE-CLOSURE.md).

`ceil(log2(1+|a|))+log2 denominator(a)`; SCALE uses max(1,|a|).
COPY and CLEAR have zero height increment. Address permutations and
fourth-root phases have zero height increment too. The scalar role word
is unchanged by the all-column lift; no additive tensor-power inference
is made.

The previously counted full expanded allowance is

```

```

Thus the individual scalar increments can be added directly along the
finite word. There is no need to first bound a dense Z-by-Z role matrix
by a generic `G*Z^2` expression. All source roles/owned centers are
actual coordinates; copying, clearing, parking and fixed monomial
wrappers do not create an additional coefficient-height factor here.
The argument concerns coefficient growth, not the cost of those actions
on a tape. Their charged data arithmetic is already in G; fixed routing
is free only in the declared circuit model.

Use the conservative fresh constant

```
E_lin=8G+8N+32, B_lin=P+E_lin.
```

The factor8 overpays the audited scalar height sum. The term8N pays the
fewer than N elementary remainder axes and32 pays fixed sign/endpoint
allowances. At a node e=Nf+r, each completed rank-f child returns a map
whose coefficients lie in2^-f Z[i] and whose absolute row sum is at most
2^f. Previously completed children therefore contribute at most P*f
to either magnitude or denominator excess. Only the currently running
child contributes its internal temporary bound A(f). This is precisely
the source completed-child argument; children are never rounded at
return. It gives

```

For a leaf A(e)<=8e. Since N>=2, f>=1 at every internal node, and
`2B_lin(N-1)>=P+E_lin`, induction gives `A(e)<=2B_lin e`.
The all-size occupied-row implementation changes neither coefficients

```

x>=x0, since k/(x+3)<c ln2 for k<=1040,c>=delta. The same endpoint
